Part 1

What Does "AI Native" Mean?

What AI Native is NOT

  • "We use ChatGPT for customer support"
  • "We have an AI chatbot on our site"
  • "Our engineers use Copilot"
  • "We fine-tuned a model once"

These are AI-assisted. Not AI-native.

What AI Native IS

System design where AI is a
first-class execution layer

Not a tool you use. An actor that does work.

The Test

Can unstructured input become
executed work product
with zero human in the loop?

The Spec Format

Repo: ~/git/client-project
Client: acme_corp
Intent: Add user authentication to the API

## Done When
- [ ] POST /login returns JWT on valid credentials
- [ ] Protected routes return 401 without token
- [ ] Tests pass with `pytest`

## Requirements
- JWT tokens with 24h expiry
- bcrypt for password hashing
- Return 401 for invalid credentials

## Technical Architecture
- FastAPI with python-jose for JWT
- SQLAlchemy for user storage

## Key Files
- src/auth.py - authentication logic
- src/routes/login.py - login endpoint
- tests/test_auth.py - auth tests

Why This Works

Checkable

Every "Done When" item is verifiable

Scoped

Key files listed explicitly

Contextual

Technical architecture specified

Executable

Claude Code can run autonomously

The Cold Start Paradox

"I need evals to ship safely"

"But I need production data for evals"

"But I can't get data without shipping"

???

The Resolution

Human-in-the-loop bootstrap

  1. Ship with human review on every action
  2. Collect rejections + reasons
  3. Categorize failures → fix prompts
  4. Graduate to spot checks
  5. Automate eval on critical paths only

Failures Are Data

Every rejection is a prompt fix
waiting to happen.

  • Don't hide failures — categorize them
  • Don't blame the model — fix the spec
  • Don't build evals in isolation — use production data

Writing Good Prompts

"Good is the absence of bad"

Don't

  • Ask same question twice
  • Use vague language
  • Assume user context
  • Return unstructured text

Do

  • Track conversation state
  • Define terms explicitly
  • Ask clarifying questions
  • Use fixed output schemas

Eval Graduation Path

StageCoverageWhen to Use
Human review all100%Launch
Spot checks + flags~20%After patterns emerge
Auto eval critical paths~5%After prompt stabilizes

Never: 100% automated coverage before shipping

Key Takeaways

  1. Specs over prose — Make requirements checkable
  2. Human-in-the-loop bootstrap — Ship with review, graduate to evals
  3. Failures are data — Each rejection = prompt fix
  4. Context is your moat — Accumulated knowledge compounds
