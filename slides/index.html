The Spec Format

Repo: ~/git/acme-api
Client: acme_corp
Intent: Add JWT-based user authentication to the REST API

## Done When
- [ ] POST /api/auth/login accepts email/password, returns JWT
- [ ] POST /api/auth/register creates user with hashed password
- [ ] Protected routes return 401 without valid token
- [ ] Token expiry is enforced (24h)
- [ ] All tests pass with `pytest tests/`

## Requirements
- JWT tokens with 24-hour expiry
- bcrypt for password hashing (cost factor 12)
- Return 401 for invalid credentials
- Email must be unique, validated format

## Key Files
Files to create:
- src/auth/jwt.py - Token creation/validation
- src/routes/auth.py - Login/register endpoints
- tests/test_auth.py - Auth tests

Files to modify:
- src/main.py - Register auth routes
- src/models/user.py - Add password_hash field

The Resolution

Human-in-the-loop bootstrap

1️⃣Ship with human review on every action
↓
2️⃣Collect rejections + reasons
↓
3️⃣Categorize failures → fix prompts
↓
4️⃣Graduate to spot checks

5️⃣Automate eval on critical paths only

Example: STOP_IGNORED

✗ Before

User: "Schedule team sync for Tuesday"
Agent: "I'll schedule that for 2pm Tuesday"

User: "STOP - I need to rethink this"
Agent: [Sends calendar invite anyway]
Agent: [Sends reminder email]
Agent: [Updates project tracker]

User: 😡 "I SAID STOP!"

23 rejections from this pattern

✓ After

CRITICAL STOP HANDLING:
If user message contains:
- "stop", "STOP", "halt", "wait"
- "hold on", "cancel", "nevermind"

Then:
1. IMMEDIATELY stop all pending actions
2. Do NOT send any invites/emails
3. Do NOT modify any calendars
4. Reply: "Stopped. No changes made.
   What would you like to change?"

23 failures → 0 failures

Failures Are Data

Every rejection is a prompt fix
waiting to happen.

✓ Don't hide failures — categorize them
✓ Don't blame the model — fix the spec
✓ Don't build evals in isolation — use production data

Writing Good Prompts

"Good is the absence of bad"

✗ Don't

  • ✗ Ask the same question twice
    "What's your name?" after they told you
  • ✗ Use vague language
    "Handle errors appropriately"
  • ✗ Assume user context
    Timezone, preferences, role
  • ✗ Return unstructured text
    Prose when you need structured data

✓ Do

  • ✓ Track conversation state
    Remember what you've already asked
  • ✓ Define terms explicitly
    "Quick sync" = 15 minutes
  • ✓ Ask clarifying questions
    When input is ambiguous
  • ✓ Use fixed output schemas
    JSON with defined structure
